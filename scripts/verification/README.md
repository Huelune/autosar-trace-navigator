# 분석 과부하 검증

GUI·고객 코드 없이 합성 프로젝트만 새 폴더에 생성해 분석한다.
실제 엔진은 별도 프로세스에서 실행하며, 배포 VSIX 안의 분석 어댑터도 UI 없이 호출한다.
Python 표준 라이브러리와 Node를 사용한다. 실행 중 인터넷이나 추가 패키지 설치는 필요하지 않다.

저장소 루트에서 Node가 PATH에 있는 경우:

```powershell
.venv\Scripts\python scripts/verification/stress_analysis.py build/overload-new --node node
.venv\Scripts\python -m unittest discover -s tests -p test_stress_analysis.py -v
```

출력 폴더는 **존재하지 않아야 한다**. 기존 5125파일 샘플이나 C/H를 수정하지 않는다.
`build/overload-new/results.json`에 실제 성공/실패·시간·메모리·응답 크기·프로세스 회수·원본 무변경을 기록한다.
어느 정상 조회라도 제한 시간/메모리/응답 상한으로 중단되면 성공으로 포장하지 않고 종료 코드 1을 반환한다.
기대된 입력 한도 오류는 부분 결과 없이 정확한 오류로 응답해야 성공이다.

| 검사 | 기대 동작 |
|---|---|
| 84파일 범위 3회 | 매번 170개 함수 반환 |
| 5125파일 전체 2회 | 매번 2755개 함수 반환 |
| 9221파일 전체 | 4899개 함수 반환 |
| 5125파일 2건 동시 | 두 응답 모두 정상, 결과 잘림/혼선 없음 |
| 10002파일 / 상한 10000 | files 한도 오류, 부분 함수 목록 없음 |
| 단일 파일 4MiB + 1바이트 | file_bytes 한도 오류 |
| 소스 합계 32MiB + 1바이트 | source_bytes 한도 오류 |
| 소스 합계 정확히 32MiB | 정상 분석 |
| 함수 정의 6001개 | 응답 5000개, truncated=true |
| 배포 어댑터 시간 초과/취소 | 실제 분석 작업 종료 확인 |
| 배포 어댑터 9MiB 출력 부하 | 기본 8MiB 응답 한도 오류 |
| 취소 후 같은 어댑터로 작은 조회 | 새 프로세스의 정상 응답 |

분석 호출은 13회, 별도로 어댑터 4항목을 검사한다. 어댑터 출력 부하는 분석 성능과 분리한
합성 stdout 폭주이며, timeout/cancel은 실제 5125파일 분석을 시작한 작업에서 확인한다.

## 자원 제한과 측정 해석

- 기본 작업별 제한은 60초(`--timeout 1..120`), 동시 작업 최대 2개, 프로세스 트리당 메모리 감시 한도 512MiB다.
- 실행 전 사용 가능 메모리가 확인되고 1536MiB 미만이면 시작하지 않는다.
- stdout은 최대 8MiB만 보관하고 stderr는 내용 대신 바이트 수만 센다.
- Windows는 `.venv` 실행기와 실제 Python이 별도 프로세스일 수 있다. PID/부모 관계로 해당 작업의 하위 프로세스를 추적하고,
  제한 초과 시 해당 트리를 종료한다. 단위 테스트도 실제 Python PID가 남지 않는지 확인한다.
- `peak_tree_mib_upper_bound`는 샘플 시점에 살아 있는 해당 트리 프로세스들의 OS peak working set 합계 중 최대값이다.
  각 프로세스의 피크 발생 시점은 다를 수 있으므로 동시 RSS의 정확한 피크가 아닌 보수적인 집계다.
  OS가 예약해 주는 엄격한 메모리 제한도 아니다. 확인 불가능한 값은 null이며 0으로 성공 처리하지 않는다.
- Windows/Linux의 PID 열거·working set/VmHWM을 사용한다. 다른 OS의 자원 계측은 검증하지 않았다.
- 생성·해시 검사·감독 Python과 OS 파일 캐시는 작업 메모리 수치에 포함되지 않는다.
- 각각 새 분석 프로세스로 실행하므로 확장 UI 캐시의 이득은 측정하지 않는다. 반복 표본이 적어 p95/장기 누수 보장을 제공하지 않는다.

샘플은 얕은 매크로와 작은 함수 위주다. 실제 고객 코드, CT 실행·RTE wiring·실시간 UI 응답성,
수십 작업의 동시 실행, 장시간 안정성 시험과 구분한다. 문제가 나오면 이 보고서를 근거로 다음 구현 범위를 정한다.

`audit_vsix.py`는 별도 압축 감사 도구다. 컴파일한 확장 폴더를 받아 release VSIX와 manifest·JS·README 링크를 비교한다.
