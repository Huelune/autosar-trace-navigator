# 예제 DB로 따라 하는 사용법

이 도구는 **원하는 분기를 만족시키기 위해 값을 어디서 준비해야 하는지 조사하고,
그 이유와 경로를 저장**합니다. C 코드를 수정하거나 CT 값을 직접 변경하지 않습니다.

처음에는 저장된 예시를 열어 보세요. 이후 같은 경로를 직접 조사하면 버튼의 역할을 익힐 수 있습니다.
모든 예제는 저장소의 가상 AUTOSAR 코드만 사용하며 실행 중 인터넷은 필요하지 않습니다.

## 1. 예제 DB 준비와 실행

Python 환경이 준비된 프로젝트 루트에서 PowerShell 명령을 실행합니다.
처음 설치한다면 [환경 구성](../README.md#환경-구성-powershell)을 먼저 진행하세요.

```powershell
.venv\Scripts\python examples\create_demo.py
.venv\Scripts\python -m autosar_trace_navigator
```

첫 명령은 **build/tutorial.sqlite3**를 만들고 두 세션의 이름과 단계 수를 출력합니다.
기존 파일은 덮어쓰지 않습니다. 이미 있다면 그대로 열거나 다음처럼 새 이름을 지정하세요.

```powershell
.venv\Scripts\python examples\create_demo.py --output build/tutorial-02.sqlite3
```

이미 만들어 둔 [examples/tutorial.sqlite3](../examples/tutorial.sqlite3)도 제공합니다.
이 DB는 작성 당시 `E:\01.Projects\autosar-trace-navigator`의 절대 소스 경로를 기록합니다.
**다른 위치에 저장소를 받았다면 위 명령으로 현재 위치에 맞는 DB를 만들어 사용하세요.**
DB에 C 본문이나 분석 범위 설정은 저장되지 않습니다.

## 2. 저장된 조사 열기

1. 상단 **세션 불러오기**를 누르고 `build/tutorial.sqlite3`를 선택합니다.
2. 세션 선택 창에서 **세션 ID**를 확인해 원하는 행을 선택합니다.
3. **선택 세션 복원**을 누릅니다.

| 세션 ID | 예시 | 저장된 단계 | 처음 보이는 위치 |
|---|---|---:|---|
| example-01-ct-global | 값 출처를 따라 CT 전역 후보까지 찾기 | 4 | RawInput CT 후보에서 추적 중지 |
| example-02-nested-conditions | 계산을 실행할 조건과 그 조건의 출처까지 찾기 | 10 | Produce 40행 계산 지점 |

두 예시는 모두 최초 목표가 `ValuePath_Consume`의 `pedal → 60`입니다.
예제 01은 입력 후보 하나를 찾는 데까지의 짧은 조사입니다. 분기에 필요한 모든 준비가 끝났다는 뜻은 아닙니다.

복원 직후에도 최초 목표·현재 조사 이유·조사 트리를 볼 수 있습니다.
코드까지 보려면 다음 분석을 진행하세요.

1. **루트 폴더 선택**에서 저장소 아래 **test/value_paths** 폴더를 선택합니다.
2. **분석 범위**에 `value_paths.c;value_paths.h`를 입력합니다.
3. **선택 범위 분석**을 누릅니다. 정상 결과는 **파일 2개 / 함수 5개**입니다.

이 과정은 복원한 조사를 유지합니다. **선택 분기로 새 조사 시작**을 누를 필요는 없습니다.
복원 후의 소스 변경 여부 미검증 표시는 저장 시점과 현재 코드의 동일성을 보장하지 않는다는 안내입니다.

## 3. 화면을 읽는 방법

왼쪽은 함수·분기 탐색, 가운데는 **현재 소스**, 오른쪽은 **후보 목록 / 비교 코드 / 이력**입니다.
소스와 비교 코드를 탭으로 번갈아 보지 않아도 됩니다. 각 영역의 경계를 드래그해 크기를 조절하세요.
분석 설정은 분석 후 접힙니다. 다시 바꾸려면 상단 **분석 설정 접기/펼치기**를 누르세요.

가운데 변수 칸은 **분기를 통과하기 위해 어느 값을 준비할지 정하는 곳**입니다.
`(eligible == 1) && (pedal >= 60u)`를 골랐다면 `eligible`, `pedal`이 따로 나옵니다.
`pedal`을 고르고 **원하는 값**에 `60`을 넣으면 “pedal을 60으로 준비할 출처를 조사”하는 목표가 됩니다.
목표가 정해지면 이 입력은 숨겨지고 최초 목표가 상단에 남습니다.
그다음 **현재 변수 조사**는 처음 목표를 유지하면서 다른 값의 출처를 살펴보는 기능입니다.

| 위치 또는 버튼 | 역할 |
|---|---|
| 상단 최초 목표·변수 목표 | 처음 조사하려던 분기와 값을 계속 표시 |
| 상단 지금 조사 | 현재 함수·추적 변수·짧은 이유 표시 |
| 가운데 소스 | 현재 위치의 읽기 전용 코드와 선택 행 표시 |
| 오른쪽 값 출처 | 초기화·대입·반환값·RTE 공급식·CT 전역 후보 조사 |
| 오른쪽 실행 조건 | 선택한 계산·쓰기 지점을 감싸는 조건의 변수 조사 |
| 오른쪽 이동 전 비교 — 후보 / 이력 코드 | 원본을 유지한 채 후보 또는 과거 단계의 코드 확인 |
| 오른쪽 출처를 찾는 값·조사 연결 | 현재 어떤 변수에서 어떤 값으로 따라가는지 구분 |
| 오른쪽 아래 근거 상세 / 조사 정보 | 불확실성·전체 이유·전체 경로·하위 조건 확인 |
| 오른쪽 아래 조사 트리 | 모든 조사 경로·선택 행·이유 보존. ▶는 현재 위치 |
| 선택한 이력 단계로 이동 | 선택한 과거 단계로 실제 조사 위치 변경 |
| 뒤로 | 현재 단계의 부모 조사로 이동 |
| 선택 라인 기록 | 소스에서 명시적으로 선택한 위치를 현재 단계에 저장 |

**후보나 이력의 행을 클릭하는 것은 미리보기입니다.** 조사 위치를 옮기려면 해당 조사 버튼이나
**선택한 이력 단계로 이동**을 눌러야 합니다. 표의 긴 경로와 이유는 가로 스크롤로 확인할 수 있습니다.

## 4. 예제 02의 조사 트리 읽기

`example-02-nested-conditions`를 복원하고 위의 소스 분석을 완료하세요.
아래 행 번호는 모두 `value_paths.c` 기준입니다. 이력 번호는 **조사 관계**이며 실행 순서가 아닙니다.

```text
1                      Consume 52행: pedal → 60 목표
└─1.1                  Produce 45행: RTE에 공급하는 next 조사
  └─1.1.1              Produce 40행: RawInput * 2 + 10 계산 조사 [시작 위치]
    ├─1.1.1.1          RawInput CT 전역 후보 → 값 추적 중지
    ├─1.1.1.2          Produce 39행: static permit != 0 조건 조사
    │ └─1.1.1.2.1      PreparePermit 27행: permit = 1 쓰기 조사
    │   └─1.1.1.2.1.1  PreparePermit 26행: EnableInput == 1 조건 조사
    │     └─1.1.1.2.1.1.1  EnableInput CT 전역 후보 → 값 추적 중지
    └─1.1.1.3          Produce 38행: ModeInput == 2 조건 조사
      └─1.1.1.3.1      ModeInput CT 전역 후보 → 값 추적 중지
```

1. 이력의 **1.1.1.1**을 클릭합니다. 오른쪽 아래 **근거 상세**에서 `RawInput=25`라는 사람이 기록한
   입력 계획을 확인하세요. 실제로 이동하면 CT 후보에서 값 추적을 멈췄다는 안내가 나옵니다.
2. **1.1.1**을 선택하고 **선택한 이력 단계로 이동**을 누릅니다.
   **실행 조건** 탭에는 `ModeInput == 0`은 거짓, `ModeInput == 2`는 참,
   `value_path_permit != 0`은 참이어야 한다는 후보가 표시됩니다.
3. **1.1.1.2** 아래를 순서대로 미리 봅니다. permit은 static이라 직접 제어 후보가 되지 않습니다.
   대신 27행에서 permit을 1로 쓰는 코드를 찾았고, 그 코드는 `EnableInput == 1`일 때 실행됩니다.
4. EnableInput CT 후보 단계로 이동하면 **조사 정보**에 permit 조건과 EnableInput 조건이 함께 남습니다.
   최초 `pedal → 60` 목표도 유지됩니다.
5. **1.1.1.3** 경로는 같은 계산의 ModeInput 조건을 별도로 조사한 기록입니다.
   이 경로를 보더라도 permit 조사 기록이 지워지지 않습니다.

## 5. 같은 조사를 직접 만들어 보기

기존 예시를 보존하려면 위 생성 명령으로 별도의 연습 DB를 준비하세요.
새 조사로 시작하면 첫 **세션 저장** 때 저장할 DB를 선택할 수 있습니다.

1. `test/value_paths`를 위 범위로 분석하고 함수 검색창에 `ValuePath_Consume`을 입력해 **검색**합니다.
2. 함수와 52행의 if 분기를 선택하고 **선택 분기로 새 조사 시작**을 누릅니다.
   이유 예: `pedal이 목표 이상이 되도록 입력 준비`.
3. 가운데 **추적할 변수** 목록에서 `pedal`을 선택하고 **원하는 값**에 `60`을 입력한 뒤
   **변수 목표 설정**을 누릅니다. 목록에 값이 여러 개면 먼저 어떤 변수를 조사할지 골라야 합니다.
4. **값 출처**에서 **RTE 공급 값** 후보를 선택해 코드를 미리 봅니다.
   **선택 출처 조사**를 누르고 이유를 입력하면 Produce의 next 조사로 이동합니다.
5. **계산 입력: ValuePath_RawInput** 후보를 같은 방법으로 따라가 40행의 계산에 도달합니다.
6. **CT 전역 제어 후보: ValuePath_RawInput**을 따라가면 제어 후보가 기록되고 값 추적이 멈춥니다.
7. 이력에서 계산 지점으로 돌아갑니다. **실행 조건**에서 `value_path_permit`이 참이어야 하는
   후보를 고르고 **조건 변수 하위 조사**를 누릅니다.
8. **값 출처**에서 **상수: 1u**를 따라가 permit을 1로 쓰는 위치로 이동합니다.
   **실행 조건**에서 EnableInput을 하위 조사하고, 다시 값 출처에서 CT 전역 후보까지 이동합니다.
9. 계산 지점으로 돌아가 `ModeInput == 2`가 참인 조건을 별도 하위 조사합니다.
   값 출처에서 ModeInput CT 전역 후보까지 기록합니다.
10. **세션 저장**으로 새 DB를 지정합니다. 다음 저장부터는 같은 DB의 세션이 갱신됩니다.
    앱을 다시 열고 **세션 불러오기**로 복원할 수 있습니다.

이유에는 `permit를 1로 만드는 분기를 조사`처럼 목적을 쓰세요.
검토한 설정값도 `입력 계획: ValuePath_EnableInput=1, CT 접근성 확인 필요`처럼 기록할 수 있습니다.
현재는 별도의 입력 계획 편집 화면이 없으므로 예제 DB는 조사 이유에 이 내용을 남겼습니다.

## 6. 조사 결과를 테스트 준비로 옮기기

다음은 수식과 코드를 **사람이 검토한** 가상 입력 예입니다. 도구가 계산해 준 결과가 아닙니다.

| 입력 후보 | 준비할 값 | 근거 |
|---|---:|---|
| ValuePath_RawInput | 25 | 25 × 2 + 10 = 60 |
| ValuePath_EnableInput | 1 | PreparePermit에서 static permit을 1로 설정 |
| ValuePath_ModeInput | 2 | 계산이 있는 else-if에 진입하고 Mode==0은 피함 |

이 값을 준비한 뒤 가상 하네스는 **PreparePermit → Produce → Consume** 순서로 실행합니다.
이 순서는 하네스와 코드를 확인해 정한 것입니다. 조사 트리의 나열 순서를 그대로 실행하지 마세요.
실제 CT에서는 전역 심볼 접근성과 설정 시점·초기화 동작을 확인해야 합니다.
static 변수나 RTE 내부 메모리가 직접 제어 가능하다고 가정하지 않습니다.

## 7. 막힐 때 확인할 것

| 보이는 상황 | 확인 방법 |
|---|---|
| 복원했는데 코드가 안 보임 | 소스는 DB에 없습니다. 현재 경로로 DB를 생성하고 `test/value_paths`의 지정 범위를 분석하세요. |
| 함수 목록이 비어 있음 | 함수 이름을 입력하고 검색하세요. 모든 함수를 자동 나열하지 않습니다. |
| CT 후보에서 값 출처가 비어 있음 | 후보 도달 시 값 추적이 멈춘 상태입니다. 계산 지점 이력으로 돌아가 실행 조건을 조사하세요. |
| 이력을 클릭해도 현재 표시가 그대로임 | 미리보기 상태입니다. **선택한 이력 단계로 이동**을 누르세요. |
| 다른 조건을 조사하면 상단 목표는 계속 60임 | 최초 pedal 목표입니다. 현재 조사 변수는 후보 위의 함수::변수에서 확인하세요. |
| b.a 또는 p->a를 골랐는데 추적 버튼이 비활성임 | 멤버·포인터 경로는 아직 역추적하지 않습니다. 객체를 무시하고 a로 연결하지 않도록 막은 상태입니다. |
| 분기 조건에 매크로가 있음 | 매크로는 자동 확장하지 않습니다. 예제 목표는 소스의 `(6u * 10u)`를 사람이 검토한 것입니다. |
| 실행 조건 목록이 비어 있음 | 감싸는 if 조건만 추출합니다. 앞선 return·루프·호출 순서까지 조건이 없다고 확정하지 않습니다. |
| 예제 생성이 기존 파일 오류로 끝남 | 기존 DB를 그대로 사용하거나 `--output`으로 새 파일 이름을 지정하세요. |

자세한 해석 한계는 [값 추적 문서](values.md), 기능별 설명은 [GUI 문서](gui.md)를 참고하세요.
