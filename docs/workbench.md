# 화면 상태 계층

workbench.py는 Tkinter 없이 분석과 세션 조작을 연결한다.

- `analyze_project(root, include_paths=..., exclude_paths=...)`는 선택 범위의 C/H를 한 번 읽고 동일 바이트로
  파서·RTE 헤더 검사·미리보기 스냅샷을 만든다. 분석 실패는 기존 화면 상태를 바꾸지 않는다.
- `Workbench.project`에 완성된 결과를 배치한다. 분석 폴더 변경 자체는 조사 세션을 삭제하지 않는다.
- `start(function_id, branch_id, reason)`는 현재 분석 결과로 새 목표를 만든다.
- `candidates()`는 현재 조사 함수의 호출 후보와 RTE 공급자 후보를 relation으로 구분한다.
  이름 기반 다중 함수 후보는 모두 남기며, 매크로/간접 호출이나 미발견 대상은 함수 미확인으로 남긴다.
- `follow(candidate, reason)`는 지금 단계의 확인 가능한 함수 후보만 허용한다.
  `back()`/`select(step_id)`는 전체 이력을 유지한다.
- `save(path)`는 성공 후에만 리비전과 dirty 상태를 갱신한다. 다른 DB로 저장하면 새 삽입이다.
- `restore(path, session_id)`는 성공 후에만 조사 상태를 교체한다. 복원은 restored로 표시한다.

후보는 실제 호출 대상이나 배포 연결을 확정하지 않는다. 복원된 함수 스냅샷과
현재 분석의 함수 메타데이터가 다르면 후보를 제공하지 않는다. 같아도 원본 바이트의
변경 여부가 검증된 것은 아니므로, 복원 화면은 항상 소스 미검증 표시를 유지해야 한다.
저장된 DB에는 전체 소스의 해시나 바이트가 없으며 자동 재연결은 제공하지 않는다.

범위별 입력 예산, 함수 검색 페이지와 스냅샷 조회 인덱스는 [범위 분석 문서](scoped-analysis.md)를 참고한다.
미확인은 현재 범위에 없거나 해석하지 못한 결과이며 프로젝트 전체의 부재 판정은 아니다.
