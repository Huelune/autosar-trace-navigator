2026-11-06, Windows x64 / Python 3.14.3 / Zig 0.15.2 C 컴파일러 환경에서 검증했다.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -m pip check
git diff --check
```

통합 검증은 정상 C/H 11개와 파서 전용 3개를 함께 검색·분석한다. 파서 전용
malformed.c에서만 구문 오류가 기록되고 정상 파일의 결과는 보존된다.
함수/분기 ID의 중복 여부, 소속 함수·부모 분기·체인 참조, 바이트 범위,
반복 분석 결과의 동일성 및 별도 번역 단위의 동명 함수 구분을 확인한다.

AUTOSAR 샘플의 목표 else-if 10행, 6단계 호출 후보 경로와 미확장 매크로 표시는
제품 파서 API로 검증했다. 원본 파일의 내용 해시와 수정 시각 불변 검증도 통과했다.

Trace Manager는 6단계 조사 중 목표 유지, 조사 이유 보존, 뒤로 이동 후 대안 경로
보존, 잘못된 이동 거부를 검증했다. SQLite는 임시 DB에서 재개 시 커서·대안 경로·
불확실성 복원, 동시 갱신 충돌, 손상 데이터 및 타 DB 거부, 저장 실패 롤백과
다른 세션 보존을 검증했다. 실제 사용자 DB는 수정하지 않았다.

RTE 단위 검증은 전체 접미사 구분, 중복 헤더, 미확장 매크로, 조건부 다중 공급자,
누락·미지원 API를 다룬다. 샘플에서 접근 7개, 데이터 연결 후보 2개를 추출했고
Speed_Raw·Pedal_Percent의 공급자 후보가 SensorAcquisition_10ms임을 확인했다.
6단계 호출 조사 뒤 공급자 후보로 이동한 8개 단계의 경로를 저장·복원하여 목표와
이름 기반 연결이라는 불확실성이 보존됨을 확인했다. 원본 해시·수정 시각도 동일했다.

GUI 테스트는 실제 Tk 위젯을 생성하여 목표·이유·읽기 전용 소스, 호출 후보 이동,
뒤로 가기, 저장·복원, 오류·취소 처리를 확인한다. 분석 워커와 Tk 이벤트 루프의
실제 연결 및 모듈 import 시 창 미생성도 검증한다. 복원 세션 선택 창의 위치와
선택 복원 콜백을 검사한다. GUI 테스트에는 데스크톱 환경이 필요하다.

값 출처 분석은 초기화/대입·반환값·매개변수·전역 쓰기·RTE 공급 후보와 해석 경계를 확인한다.
pedal 목표에서 TestPlatform_Reset 호출 인수 60u까지 조사하고 변수 목표·단계별 선택 위치·
현재 추적식을 저장·복원했다. 기존 JSON 형식의 선택 위치 미기록 복원과 미래 형식 거부도 확인한다.
GUI에서는 후보/이력 미리보기의 커서·dirty·소스 선택 불변, 미확인 대상의 근거 코드 표시,
현재 분석과 함수 불일치 시 미리보기 거부, 명시적 이력 이동 후 기록 행 복귀를 검증한다.
한글 주석·CRLF의 바이트 위치, 실제 Tk 마우스 릴리스 이벤트와 버튼 콜백, 1100×760 창에서
변수 목표·이력 컨트롤 노출도 확인했다. 이 추가 기능의 사람 손 클릭 검증은 별도로 수행하지 않았다.

별도로 일반 실행 환경에서 마우스로 폴더 분석·목표 선택·호출 2단계·RTE 공급자 이동·
이력 이동·저장·앱 재시작 후 복원까지 확인했다. 클릭 검증에서 발견한 복원 창의
화면 밖 배치를 중앙 정렬로 수정했다. 샌드박스의 자동 텍스트 입력 제약은
일반 실행 환경에서 재검증하여 한글 입력을 확인했다. [세부 기록](gui.md)을 참고한다.

후속 범위 분석에서는 미선택 폴더에 진입하지 않는지, 파일 수 제한이 소스 읽기 전
적용되는지, 바이트 예산 초과가 파싱 전 거부되는지 확인했다. 범위를 넓히면 기존
미확인 호출과 RTE 공급자 후보를 발견하면서 목표·이력을 유지했다.
550함수의 검색 결과는 API·Tk GUI에서 페이지당 100개(현재 조사 함수 별도 최대 1개)로
제한됐다. 루트 선택만으로 자동 전체 분석하지 않는 것과 최소 창 크기에서 주요 컨트롤
노출도 검증했다. 이는 가상 코드 검증이며 실제 대형 프로젝트 성능 보장은 아니다.

확장 프로젝트의 C/H 171개에서 함수 정의 424개, 분기 665개, RTE 접근 172개와
연결 후보 52개를 추출했다. 모든 SWC의 6단계 호출 경로, 동명 static 함수·조건부
대안, 다중 공급자·헤더 매크로 불확실성, 검색 페이지, 범위 확장 후 세션 복원을 검증했다.
생성기가 같은 내용을 재현하고 기존 출력 폴더를 거부하는지 확인했다.
80 SWC/563파일 변형은 전체 범위의 예산 거부와 선택 범위의 정상 분석을 검증했다.
전체 테스트는 Zig 파일 접근 오류를 피하기 위해 일반 실행 환경에서 실행했고,
확장 기본 샘플 192개 C 시나리오가 모두 통과했다. 80 SWC C 전체 실행은 하지 않았다.
[확장 샘플 안내](large-sample.md)를 참고한다.

이번 결과는 구문·이름 기반 RTE 후보 분석과 가상 실행의 검증이다. 실제 C 심볼 연결,
ARXML 배포 연결·실행 순서 해석, ECU 실행, 전체 분기 커버리지 측정을 포함하지 않는다. Python 3.11~3.13 및
다른 OS는 이번 실행에서 검증하지 않았다. 링크 제외 테스트는 Windows 링크 생성
권한에 의존하지 않도록 분류를 모의 처리한다.

초기 환경 준비 때 로컬 wheel만 이용한 `--no-index` 재설치도 검증했다.
현재 스캐너·파서는 네트워크 접근이나 전처리기 실행을 요구하지 않는다.
