# 변수값을 만들기 위한 역추적

핵심 목표는 소스를 편집하는 것이 아니라 **선택한 분기를 만족시키려는 변수값이
어디에서 공급되는지 찾아 테스트 입력을 준비하는 것**이다.

dataflow.ValueResolver는 ProjectSnapshot의 바이트를 사용해 필요한 파일만 구문 분석한다.
ValueProbe는 함수 ID·추적식·소스 사용 위치·변수 또는 반환값 종류를 기록한다.
sources(probe)는 ValueSource 후보(종류·표현식·근거 위치·다음 probe·불확실성)를 반환한다.

지원하는 후보는 단순 변수의 이전 초기화/대입, 함수 반환값, 호출 인수와 매개변수,
명시적 Rte_Read 출력 변수의 Rte_Write 공급 값, 같은 파일 전역 변수의 쓰기 지점이다.
상수·외부 호출·미지원 복합 표현식은 입력/해석 경계로 표시한다. 원본 파일은 수정하지 않는다.

기존 샘플의 pedal은 다음 경로로 조사할 수 있다.

```text
IsAssistRequested: pedal >= 60u
  ← Rte_Read_Pedal_Percent(&pedal)
  ← SensorAcquisition_10ms: Rte_Write_Pedal_Percent(pedal)
  ← pedal = IoHwAb_ReadPedalPercent()
  ← return hardware_pedal
  ← TestPlatform_Reset: hardware_pedal = pedal
  ← 호출 인수 60u 또는 테스트 테이블의 item->pedal
```

초기값 pedal=0u도 후보로 보존한다. 여러 조건부 대입·공급자는 모두 후보이며,
어느 대입이 실제 도달하는지는 증명하지 않는다. 위치 이후의 쓰기는 해당 사용
위치의 출처로 제공하지 않는다. 같은 줄에서는 정확한 사용 위치를 선택해야 한다.

## 해석 한계

- 제어 흐름·도달 정의·변수 shadowing·별칭·포인터 쓰기·호출 컨텍스트를 확정하지 않는다.
- 직접 추적 변수는 단순 C 식별자다. 구조체 멤버·배열·복합 포인터 표현식은 경계로 남긴다.
- 같은 이름의 함수/전역 쓰기 연결은 후보다. 전역 쓰기는 같은 파일 안에서만 찾는다.
- RTE 관계는 이름 기반 후보이며 ARXML·실행 순서는 기존 Resolver와 마찬가지로 미확정이다.
- 매크로는 확장하지 않는다. 알려지지 않은 호출의 단순 변수 인수는 검토 후보로만 제공한다.
- 반환 수식 raw+1 등은 피연산자 후보를 제공하지만 목표값에 맞게 자동 역산하지 않는다.
- 목표값 60을 설정해도 출처 상수 0이 바뀌거나 조건이 충족됐다는 뜻은 아니다.
  입력 설정·공급자 실행 순서·다른 AND 조건은 테스트 코드에서 별도로 확인해야 한다.

조건 `(eligible == 1) && (pedal >= 60u)`에서 실제 목표 도달을 위한 기존 샘플 입력은
TestPlatform_Reset(300u, 60u, E_OK, E_OK) 후 공급자→소비자 순서 실행이다.
자동 테스트는 이 설정의 실행과 역추적 후보 경로를 각각 검증한다.
