# 변수값을 만들기 위한 역추적

핵심 목표는 소스를 편집하는 것이 아니라 **선택한 분기를 만족시키려는 변수값이
어디에서 공급되는지 찾아 테스트 입력을 준비하는 것**이다.
목표값 리터럴이 소스에 존재할 필요는 없다. 외부에서 제어할 수 있는 입력 또는 값을
만드는 계산 지점을 찾고, 그 지점의 실행 조건도 독립적인 하위 조사로 이어간다.

dataflow.ValueResolver는 ProjectSnapshot의 바이트를 사용해 필요한 파일만 구문 분석한다.
ValueProbe는 함수 ID·추적식·소스 사용 위치·변수 또는 반환값 종류를 기록한다.
sources(probe)는 ValueSource 후보(종류·표현식·근거 위치·다음 probe·불확실성)를 반환한다.

지원하는 후보는 단순 변수의 이전 초기화/대입, 함수 반환값, 호출 인수와 매개변수,
명시적 Rte_Read 출력 변수의 Rte_Write 공급 값, 같은 파일 전역 변수의 쓰기 지점이다.
상수·외부 호출·미지원 복합 표현식은 입력/해석 경계로 표시한다. 원본 파일은 수정하지 않는다.

기존 샘플의 pedal은 다음 경로로 조사할 수 있다.

```text
IsAssistRequested: pedal >= 60u
  ← Rte_Read_Pedal_Percent(&pedal)
  ← SensorAcquisition_10ms: Rte_Write_Pedal_Percent(pedal)
  ← pedal = IoHwAb_ReadPedalPercent()
  ← return hardware_pedal
  ← TestPlatform_Reset: hardware_pedal = pedal
  ← 호출 인수 60u 또는 테스트 테이블의 item->pedal
```

초기값 pedal=0u도 후보로 보존한다. 여러 조건부 대입·공급자는 모두 후보이며,
어느 대입이 실제 도달하는지는 증명하지 않는다. 위치 이후의 쓰기는 해당 사용
위치의 출처로 제공하지 않는다. 같은 줄에서는 정확한 사용 위치를 선택해야 한다.

## 해석 한계

- 제어 흐름·도달 정의·변수 shadowing·별칭·포인터 쓰기·호출 컨텍스트를 확정하지 않는다.
- 단순 식별자·구조체 멤버·명시적 역참조를 추적한다. 배열·포인터 산술은 경계로 남긴다.
- 같은 이름의 함수/전역 쓰기 연결은 후보다. 단순 전역은 같은 파일, 구조체 전역은 선택 범위의 파일 간 쓰기도 찾는다.
- RTE 관계는 이름 기반 후보이며 ARXML·실행 순서는 기존 Resolver와 마찬가지로 미확정이다.
- 매크로는 확장하지 않는다. 알려지지 않은 호출의 단순 변수 인수는 검토 후보로만 제공한다.
- 반환 수식 raw+1 등은 피연산자 후보를 제공하지만 목표값에 맞게 자동 역산하지 않는다.
- 목표값 60을 설정해도 출처 상수 0이 바뀌거나 조건이 충족됐다는 뜻은 아니다.
  입력 설정·공급자 실행 순서·다른 AND 조건은 테스트 코드에서 별도로 확인해야 한다.

조건 `(eligible == 1) && (pedal >= 60u)`에서 실제 목표 도달을 위한 기존 샘플 입력은
TestPlatform_Reset(300u, 60u, E_OK, E_OK) 후 공급자→소비자 순서 실행이다.
자동 테스트는 이 설정의 실행과 역추적 후보 경로를 각각 검증한다.

## 목표와 이력 저장

Workbench.set_variable_goal(variable, target_value, location)는 현재 조사 함수에
첫 변수 목표를 고정한다. 최초 분기와 이 목표는 이동·뒤로 가기·저장 후 복원에도 유지된다.
다른 변수 목표는 새 조사로 시작한다. inspect_variable(variable, location)는 최초 목표를
바꾸지 않고 현재 단계의 조사 변수만 바꾼다.

value_candidates()는 선택한 함수에서 필요한 값 출처를 제공한다. 후보를 follow하면
다음 함수/변수 또는 반환값 probe로 이어진다. 상수·미지원 식 같은 종점 후보로
이동하면 그 코드 위치를 기록하고 자동 값 추적은 멈춘다. 수식이나 조건이 풀린 것은 아니다.

각 TraceStep의 selected_location은 해당 함수 안에서 선택한 위치이고 evidence는
그 단계로 이동하게 된 공급/호출 근거다. 루트 단계는 최초 분기 위치를 기록한다.
record_location(location)은 사용자가 명시적으로 선택한 위치만 현재 단계에 반영한다.
미리보기·단순 코드 열람은 이 메서드를 호출하지 않아야 한다.

JSON 스냅샷 형식 2는 변수 목표, 단계별 probe와 선택 위치를 보존한다. 멤버·역참조·투영 반환값은 형식 3을 사용한다.
SQLite 테이블 버전은 그대로이며 이전 형식 1도 읽는다. 이전 기록에 없던 선택 위치는
None(미기록)으로 복원하고 임의로 추정하지 않는다. 구버전 앱의 새 스냅샷 읽기는 보장하지 않는다.

## GUI 연결

가운데 **이 분기에서 어떤 값을 준비할까요?**에서 조건 변수와 원하는 값을 고른다.
**변수 목표 설정**은 최초 목표를 고정하고, **현재 변수 조사**는 최초 목표를 유지하며 probe만 바꾼다.
목표 고정 후에는 목표값 입력이 숨겨지며 상단에 최초 목표가 표시된다.
**값 출처**는 기존 호출/RTE 탭과 별도로 제공한다. 후보 선택은 오른쪽 코드 미리보기만 수행하고,
이유를 입력해 **선택 출처 조사**를 실행해야 단계가 추가된다.
소스 클릭은 바이트 위치로 변환하며, 위치만 저장할 때는 **선택 라인 기록**을 사용한다.
후보 코드와 현재 소스는 다른 위젯을 사용하므로 후보 열람이 소스 선택 위치를 덮어쓰지 않는다.
사용 순서는 [GUI 안내](gui.md#원하는-변수값의-출처-조사)를 참고한다.

`Workbench.branch_inputs(branch_id)`는 변수 선택을 위해 조건의 식과 위치를 반환한다.
`eligible`과 `pedal`은 별도 입력이며, `b.a`, `p->a`도 전체 경로를 유지한 입력이다.
`table[i]`는 분해하지 않은 미지원 경로다. 멤버 이름 a만으로 다른 객체를 연결하지 않는다.
전체 객체 복사·명시적 별칭·함수/RTE 출력 인수와 별도 객체 출처 후보는 [구조체 안내](structs.md)를 참고한다.

## CT 제어 후보와 실행 조건의 하위 조사

- `ct_global_input`은 분석 소스 또는 헤더에서 외부 연결 이름으로 보이는 전역 선언을 찾은 후보다.
  static·const 선언과 로컬 변수는 제외한다. 헤더 가시성·빌드 연결·CT 접근성은 확인하지 못한다.
  RTE API 이름만으로 내부 메모리를 CT에서 수정 가능하다고 판단하지 않는다.
- 후보를 선택하면 해당 사용 위치를 조사 종점으로 기록한다. CT 값을 실제로 쓰거나
  이 입력으로 최초 목표가 충족됐다고 표시하지 않는다. 제어 가능한 전역을 찾았다면 사용자가
  CT 설정을 준비하고, 값을 만드는 코드가 필요하면 실행 조건의 하위 조사를 진행한다.
- `ValueResolver.conditions(site)`는 공급·계산 지점을 감싸는 if/else-if/else 조건을 추출한다.
  else-if/else에서는 앞선 조건들의 거짓도 요구한다. 각 조건은 필요한 참/거짓과 단순 변수 사용 위치를 가진다.
- `Workbench.execution_candidates()`는 현재 선택 위치와 이동 근거의 조건 변수를 별도 자식 단계로 조사한다.
  조건 조사에서도 값 출처 → 다른 쓰기 → 그 쓰기의 실행 조건을 반복해서 따라갈 수 있다.
  하위 조건의 참/거짓 요구는 단계의 불확실성 메타데이터에 보존되고 저장 후에도 표시된다.
- 다른 조건은 이력에서 같은 계산 지점으로 돌아가 새 자식으로 조사한다. 번호 1.1/1.2 등은
  조사 트리 경로이며 실제 실행 순서가 아니다. 최초 목표와 현재 하위 조건을 구분한다.

조건식·산술식은 자동으로 풀지 않으며 서로 다른 하위 조건의 일관성·충족 여부를 판정하지 않는다.
구조적으로 감싸는 if 조건만 다루므로 앞선 조기 return, 루프, switch, goto 또는 호출 간 실행 순서까지의
전체 도달 조건은 제공하지 않는다. 조건이 비어 있다고 무조건 실행된다는 뜻이 아니다.
미확장 매크로·배열·포인터 산술 등 미지원 조건식은 검토 위치로 남기며 확정된 변수로 치환하지 않는다.
[목표 상수 없는 가상 예제](../test/value_paths/README.md)에서 계산·중첩 조건·CT 후보를 함께 검증한다.
