# Branch Investigation VS Code P0 구현·검증 결과

## 결과와 범위

결과물은 **TypeScript VS Code 확장**이다. Tkinter 화면을 삽입하지 않았고 기존 프로그램을 따로 실행하지 않는다.
코드 선택 → 목표·필수 이유 → 자동 저장 → 조사 트리 → 상세 이유 → 검증된 소스 범위로 복귀하는 P0 흐름을 구현했다.
수동 스니펫·메모 편집·상태·대체 경로·부모·독립 방문 이력·복원·복구도 포함한다.

사용자가 제공한 `05_Codex_VSCode확장_구현지시서.md`는 변경하거나 구현 커밋에 포함하지 않았다.
작업 시작 기준은 `06f707e`였으며 미추적 지시서 폴더가 있는 것을 확인하고 진행했다.

추가 기록(2026-11-11): 인계 시 원본 지시서가 누락된 문제를 확인해
[TASK-003](../work/tasks/TASK-003.md)에서 [원본 지시서](05_Codex_VSCode확장_구현지시서.md)를 공유 대상으로 추가했다.
위 두 문장은 당시 구현 커밋의 기록이며 현재 지시서도 저장소에 포함한다.

확장 폴더의 상대 경로를 표기했다. **기존 Python src·tests·SQLite·uv.lock은 변경하지 않았다.**
P0 조사 기록은 기존 FunctionDefinition/TraceSession으로 위장하지 않는 독립 도메인이다.
기존 Python 엔진의 실제 호출/RTE/값/조건 후보 조회는 지시서의 **P1**이며 이번에 구현했다고 주장하지 않는다.
그때 승인된 Python subprocess의 DTO에서 기존 API를 호출하고 바이트/인코딩 ↔ UTF-16을 검증해야 한다.

## 실제 실행한 검증

환경: Windows x64, Node.js 22.23.4, TypeScript 5.9.3, VS Code 1.145.2, VSCE 4.1.0.
Node는 공식 배포 ZIP의 SHA256을 검증한 뒤 build/tools에 준비했고 npm 개발 의존성은 잠금 파일에 기록했다.

Host 기록 검사는 실제 VS Code 문서·Selection·명령·TreeDataProvider·Webview·소스 열기를 사용했다.
이유 입력 중 활성 편집기를 다른 가상 파일로 바꾸는 테스트에서도 명령 시작 당시 URI·버전·스니펫이 저장됐다.
한글·이모지·CRLF·끝 exclusive, 빈 이유/취소 무변경, 보류 Writer와 형제 경로, 구분된 CT 근거,
미저장 버퍼 변경·파일 삭제 시 이동 거부, 스니펫만 있는 기록, back/forward 시 Step/Edge 불변을 확인했다.
이모지의 surrogate pair 중간에서 끊긴 선택은 UTF-8 치환 지문으로 잘못 일치시키지 않고 거부한다.

Host의 입력창 응답과 수동 스니펫 문자열은 테스트 포트로 제어했다. 이를 보완해 별도 native UI에서
실제 입력창·우클릭·트리·여러 줄 입력·Webview 저장을 직접 조작하고 JSON의 두 단계·메모·줄바꿈을 확인했다.
본 검증의 CT 실측 라벨은 테스트용 데이터이며 **실제 CT/ECU 실행을 검증한 결과가 아니다.**

test-electron이 기본으로 신뢰 검증을 끄는 것을 발견해, 미신뢰 테스트는 라이브러리를 거치지 않고
독립 테스트 프로필의 VS Code CLI로 실행했다. 사용자 VS Code 신뢰 설정이나 기존 확장 폴더는 변경하지 않았다.
수동 검증에서 보인 일시적인 ‘저장 실패’ 문구는 저장 중 상태를 분리해 수정하고 Host 회귀를 재실행했다.

## 실행·설치와 산출물

- 확장 소스: `extensions/branch-investigation/`
- VSIX: **`build/branch-investigation-0.1.0.vsix`**
- 가상 수동 확인 기록: `build/branch-native-TNOypo/manual-workspace/.branch-investigation/workspace.json`
- 설치된 최종 패키지 Host 로그: `build/branch-host-jZtRjG/host.log`
- 패키지 설치 경로 기록: `build/branch-package-installed.json`

build 산출물과 가상 조사 기록은 Git에 넣지 않았다. VSIX는 로컬 배포물이며 Marketplace에는 게시하지 않았다.
최종 VSIX SHA256: `a3ba5b4a73c0c0468ede38fc2c411714a46167e9cbbb49fc680468368b811444`.

F5는 확장 폴더 자체를 VS Code에서 열고 `npm ci` 후 **분기 조사 확장 실행**을 선택한다.
실제 자동 Host 검증은 F5와 같은 extensionDevelopmentPath를 CLI로 전달했다. F5 키 자체는 별도로 누르지 않았다.
사용자 설치는 VS Code의 `Install from VSIX…`에서 위 파일을 선택하면 되며 Node·Python은 필요하지 않다.
[상세 실행법·5분 확인 절차](../../extensions/branch-investigation/README.md)를 참고한다.

## 완료와 후속

P0 구현·핵심 UI 수용 기준·저장/복원·패키징을 완료했다.
P1의 자동 분석 후보 조회·일괄 붙여넣기·검색/필터·앵커 후보 복구·SQLite 읽기 import는 포함하지 않는다.
P2 그래프·대규모 성능, CT 자동 조작·입력 자동 설정·실행 가능성 증명도 범위 밖이다.

이번에 실행하지 않은 검증은 macOS/Linux, 다른 VS Code/Node 버전, 다중 루트/원격 위치,
Ctrl+Alt+I 독립 키 조작의 재현, 실제 CT 실행, P1 바이트 좌표 변환이다.
Ctrl+Alt+I는 manifest와 우클릭 메뉴에 등록되어 있지만 핵심 native 저장 검증은 우클릭 경로로 수행했다.
Python 엔진을 수정하지 않아 무관한 전체 Python 회귀는 이번 확장 작업에서 반복하지 않았다.

현장 배포 전에는 승인 PC의 VS Code·오프라인 VSIX 설치 허용 여부와 로컬 저장·백업·보존 정책을 확인한다.
Python 실행 승인은 P1 연동 전에 확인한다. 고객 소스/CT 자료를 개발 PC나 Codex로 전달하는 절차는 없다.
