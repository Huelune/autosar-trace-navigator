# VS Code 확장 구현을 이어받는 순서

1. **[원본 구현 지시서](05_Codex_VSCode확장_구현지시서.md)**: 제품 목적, 사용자 흐름, 데이터·명령·저장 계약,
   P0/P1/P2 범위와 수용 기준을 읽는다. 요약 문서로 대체하지 않는다.
2. **[P0 구현·검증 결과](P0_구현_검증결과.md)**: 이미 구현한 기능, 당시 실제 검증과 미검증을 확인한다.
3. **[현재 상태](../work/STATUS.md)**와 배정 작업 카드: 최신 진행·변경·다음 행동을 확인한다.
4. **[확장 소스와 개발 방법](../../extensions/branch-investigation/README.md)**을 읽고 실제 코드/Git 상태와 대조한다.

원본 지시서는 최초 P0 요청 당시의 문서로 그대로 보존한다. 거기에 “이번 구현”이라고 적힌 P0는 이미 구현돼 있다.
원본 명세, 현재 구현/검증 기록, 이번에 배정된 작업 범위를 함께 읽고 진행하며 P0를 처음부터 다시 작성하지 않는다.

P1 중 Python 엔진 연결은 **구현돼 main에 있다**. 호출·RTE Writer 후보는 [TASK-002](../work/tasks/TASK-002.md),
값 출처·실행 조건 후보는 [TASK-004](../work/tasks/TASK-004.md)에 범위와 검증이 있다. 함수 검색과 조회 결과 재사용은 [TASK-016](../work/tasks/TASK-016.md)에서 연결했다.
엔진 쪽을 고칠 때는 UTF-8 바이트/인코딩과 VS Code UTF-16의 변환, 요청 제한·취소·실패와 후보 불확실성을 계속 보존한다.
P1의 다른 항목과 P2는 원본 지시서 11절에서 확인한다. 카드나 명세를 읽는 것만으로 별도 작업을 배정받은 것은 아니다.

원본에 언급된 옛 로컬 경로·커밋·도구 상태는 과거 참고값이다. 현재 체크아웃의 환경을 사용한다.
`starter/investigation_bridge.py`는 선택적 이전 시제품 설명이며 이 저장소의 필수 첨부물이 아니다.
