# Tkinter GUI

프로젝트 루트의 설치된 환경에서 실행한다.

```powershell
.venv\Scripts\python -m autosar_trace_navigator
```

## 조사 흐름

1. **루트 폴더 선택**으로 기준 폴더를 정한다. 이 동작만으로 분석을 시작하지 않는다.
   분석 범위에 파일·폴더를 `;`로 구분해 입력하고 **선택 범위 분석**을 누른다.
   예: test/를 루트로 선택한 뒤 `src/BrakeControl.c;src/AssistDecision.c;include`.
   전체 루트를 의도할 때만 `.`을 입력한다. 기본 제외는 .git, .venv, build, wheelhouse다.
2. 함수 검색창에 `BrakeControl` 등을 입력하고 **검색** 또는 Enter를 누른다.
   결과는 100개씩 표시하며 **이전/다음**으로 이동한다. 이름과 상대 경로로 좁힐 수 있다.
   결과에서 BrakeControl_10ms를 선택한다. 가운데에 분석 시점 소스와
   라인 번호가 표시된다. 아래 분기 목록에서 ASSIST의 else_if를 고른다.
3. **선택 분기로 새 조사 시작**을 눌러 조사 이유를 입력한다.
4. 상단 최초 목표를 유지한 채 **호출 후보**에서 조사할 대상을 선택한다.
   근거 위치와 불확실성을 확인하고 **호출 후보 조사**로 이동 이유를 기록한다.
5. 데이터 공급자를 조사할 때는 별도의 **RTE 공급자 후보** 탭을 사용한다.
   후보는 이름 기반이며 실제 호출이나 배포 연결을 확정하지 않는다.
6. **뒤로** 또는 **전체 조사 이력 → 선택한 이력 단계로 이동**으로 돌아간다.
   이력은 삭제되지 않는다. 함수 목록만 선택하는 것은 소스 열람이며 조사 위치를 바꾸지 않는다.
7. **세션 저장**으로 .sqlite3/.db를 지정한다. 이후 저장은 같은 DB에 리비전을 확인하여 갱신한다.
8. 앱을 다시 열고 **세션 불러오기**에서 DB와 세션을 선택한다.
   소스 폴더를 다시 분석하기 전에도 목표·이유·이력·커서를 볼 수 있다.

## 상태와 제약

- 소스와 진단은 읽기 전용이다. 미리보기는 분석 때 읽은 바이트이며 현재 디스크 내용과 다를 수 있다.
- 상단에 최초 목표·현재 함수·조사 이유·현재 경로를 표시한다. 제목의 `*`는 미저장 변경이다.
- 새 조사 시작, 세션 교체 또는 종료 시 미저장 변경이 있으면 버릴지 확인한다.
- 기존 조사를 유지한 채 다른 폴더를 분석할 수 있다. 실패 시 기존 분석·조사는 보존한다.
- 함수 전체를 자동으로 나열하지 않는다. 현재 조사 함수는 검색 결과 밖이어도 별도로 유지한다.
  표시 상한은 검색 100개 + 현재 함수 1개다. 검색은 조회 범위를 바꾸지만 조사 위치를 바꾸지 않는다.
- 현재 분석 루트와 범위를 표시한다. 범위 밖에서 필요할 수 있는 함수·공급자는
  "현재 분석 범위에서 미확인"으로 다루며 시스템에 없다고 확정하지 않는다.
- 필요하면 범위 항목을 추가해 다시 분석한다. 현재 함수를 계속 포함해야 후보 탐색을 이어갈 수 있다.
  관련 RTE 헤더도 명시적으로 포함해야 하며 include를 자동 추적하지 않는다.
- 기본 분석 예산은 500파일·파일당 4 MiB·소스 합계 32 MiB다. 초과 시 기존 상태를 유지하며
  범위를 줄이라는 오류를 표시한다. 입력 예산은 전체 RAM 사용량의 상한은 아니다.
- 진단 탭은 현재 범위 진단 중 최대 500개만 표시한다. 진단 총수와 표시 제한을 함께 알린다.
- 분석은 워커에서 수행하고 Tk 위젯은 메인 스레드에서만 갱신한다. 분석 중 작업 버튼을 잠근다.
  분석 중 종료해도 실행 중인 워커를 강제 중단하지는 않는다.
- 매크로·간접 호출 또는 이름이 발견되지 않은 후보는 대상 미확인으로 표시하고 조사 이동을 허용하지 않는다.
- 함수 이름이 여러 파일에서 같으면 각 후보를 표시한다. 심볼 스코프 연결은 자동 확정하지 않는다.
- 복원 또는 조사 중 재분석하면 소스 미검증 표시를 유지한다. 저장된 함수와 현재 분석의
  메타데이터가 다르면 후보를 제공하지 않는다. 같아도 전체 소스 동일성을 보장하지 않는다.
- 원본 소스·분석 인덱스·분석 폴더 설정은 DB에 저장하지 않는다. 복원 후 소스를 다시 분석해야
  후보 탐색을 계속할 수 있다. GUI는 분석·배포 연결의 확정 도구가 아니다.
- 저장 충돌·파일 접근·DB 오류는 메시지로 알리며 실패한 저장을 완료로 표시하지 않는다.
- GUI 자동 테스트는 실제 Tk 창을 생성하므로 데스크톱/Tk 런타임이 필요하다.

## 클릭 검증

2026-11-06 초기 GUI 버전에서 실제 마우스·키보드로 다음을 확인했다.

- test/ 분석(오류 사례 포함 14파일·23함수), 함수와 목표 else-if 선택 및 소스 행 강조.
- 한글 이유 입력 후 BrakeControl_10ms → EvaluateBrakeMode → IsAssistRequested 이동.
- 별도 RTE 탭의 Pedal_Percent 공급자 후보 SensorAcquisition_10ms로 이동.
- 최초 목표 고정, 단계별 이유·현재 경로 표시, 뒤로 가기와 이력 재선택.
- 파일 선택 창을 이용한 테스트 DB 저장, 앱 재시작 후 세션 선택·복원.
- 복원 창이 화면 밖에 걸리던 배치를 부모 창 중앙으로 수정하고 재검증.

샌드박스 실행에서는 자동 텍스트 입력이 반영되지 않았으나 일반 실행 환경에서는
한글 입력까지 확인했다. 위 클릭 검증은 일반 실행 환경에서 수행했다.
6단계 전체 호출 경로는 자동 테스트로 검증했으며, 수동 클릭 경로는 위 두 호출과 RTE 이동이다.

후속 범위·검색 UI는 실제 Tk 위젯 테스트로 확인했다. 루트 선택 시 분석 미시작,
빈 범위 거부, 검색과 현재 함수 유지, 550함수의 페이지별 표시 상한, 검색어 변경 시
페이지 초기화, 1100×760 창에서 범위·검색·조사 시작 컨트롤 노출을 검증했다.
대형 고객 프로젝트 벤치마크나 증분 캐시는 아직 구현하지 않았다.
