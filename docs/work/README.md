# 저장소로 작업 이어가기

이 폴더는 Codex·Claude Code·사람이 공유하는 작업 기록이다. AI 대화나 개인 메모리를 다른 PC에 복사할 필요가 없도록
**해야 할 일은 작업 카드, 실제 수행한 일은 세션 기록, 현재 개요는 STATUS**에 남긴다. 자동 동기화 서비스는 아니다.

## 파일의 역할

| 위치 | 내용 |
|---|---|
| [STATUS.md](STATUS.md) | 현재 제품 상태·검증 근거·작업 목록. 세부 진행 상태의 기준은 각 카드 |
| `tasks/<ID>.md` | 한 작업의 범위·완료 조건·상태·담당·브랜치·최신 인수인계 |
| `sessions/<UTC>-<tool>-<random>.md` | 한 작업 세션의 실제 변경·검증·미검증·다음 행동 |
| `templates/` | 생성기 없이도 복사해서 쓸 수 있는 작업/세션 양식 |
| 루트 `CHANGELOG.md` | 제품/개발 방식의 변경 요약. 상세 세션 기록을 대신하지 않음 |

상태는 `planned` → `in_progress` → `review` → `done`을 사용하고, 진행 불가 사유가 있으면 `blocked`로 기록한다.
`done`은 카드의 완료 조건을 충족했을 때만 쓴다. 계획의 존재는 구현 승인이 아니다.

## 작업 시작

1. `git status --short`, `git log -5 --oneline`을 확인한다. 사용자 변경은 그대로 보존한다.
2. 사용자가 공유 갱신을 요청한 경우 `git fetch origin` 후 대상 브랜치/커밋을 확인한다.
   깨끗한 해당 브랜치에만 `git pull --ff-only`를 사용한다. 분기되면 자동 reset/force하지 말고 변경을 비교한다.
3. `AGENTS.md`, `STATUS.md`, 배정받은 작업 카드와 최신 연결 세션을 읽는다. 실제 코드와 기록이 다르면 차이를 기록한다.
4. 카드의 담당·브랜치·상태를 갱신하고 세션을 만든다. 새 브랜치는 기본 `codex/<ID>-<짧은주제>`를 사용한다.
   `git switch -c ...`는 현재 변경·브랜치·원하는 기준 커밋을 확인한 다음에만 수행한다.
5. 구현 전 범위와 검증 계획을 알린다. 승인받은 작업만 진행한다.

Python 표준 라이브러리 생성기를 루트에서 쓸 수 있다. 기존 파일을 덮어쓰지 않고, Git 상태를 변경하지 않는다.

```powershell
python scripts/worklog.py list
# 실제 배정된 새 작업에만 생성 (예시 ID)
python scripts/worklog.py new TASK-010 --title "작업 제목"
python scripts/worklog.py start TASK-010 --tool codex --actor dev-a
# 다음 PC/Claude 세션은 같은 카드에 새로운 세션 파일 생성
python scripts/worklog.py start TASK-010 --tool claude --actor dev-b
```

`actor`는 PC/계정 실명 대신 짧은 별칭을 사용한다. 생성기는 담당 확정·작업 상태 변경·커밋·push를 자동으로 하지 않는다.
생성 후 카드의 담당과 최신 세션 링크를 직접 갱신한다. Python이 없으면 templates를 복사하고 토큰을 채워도 된다.

## 세션 중·종료·인수인계

- 의미 있는 변경마다 카드의 체크리스트와 세션의 실제 변경을 갱신한다. 미완료 작업을 완료 목록으로 옮기지 않는다.
- 실행한 정확한 명령·결과/개수·환경을 기록한다. 실패·skip·아직 안 한 검사는 별도로 쓴다.
  로그가 build 아래에만 있으면 다른 PC에 없으므로, 비민감 결과 요약을 세션에 함께 남긴다.
- 중단할 때는 수정 파일, 실패 원인, 재현 명령, **다음 첫 행동**을 남긴다. 다른 도구에 넘기기 전 미커밋 변경 유무도 기록한다.
- 코드와 필수 테스트·CHANGELOG·해당 작업 카드/세션을 논리적 단계별로 커밋한다. 검증 미완료면 그 사실을 알리고 done으로 처리하지 않는다.
- 원격 공유는 사용자 요청이 있을 때 push한다. 로컬 커밋만으로 다른 PC에 전달됐다고 보고하지 않는다.
  넘기는 사람은 브랜치와 마지막 공유 커밋을 전달하고 받는 사람은 그 커밋을 확인한다.
- 세션 파일은 과거 기록이다. 잘못된 검증 기록은 숨겨 지우지 말고 정정 내용을 덧붙인다.
  카드의 최신 상태는 수정할 수 있으며 과거 상태는 Git 이력이 보존한다.

## 두 도구가 동시에 작업할 때

Git의 카드 담당 표시는 분산 잠금이 아니다. **동일 작업은 한 번에 한 담당만** 맡고 사용자와 인계 시점을 정한다.
다른 작업은 별도 브랜치/체크아웃에서 수행한다. push하지 않은 담당 변경은 상대 PC에 보이지 않는다.
담당 카드와 파일 범위가 겹치면 먼저 조율한다. 공유되지 않은 같은 ID를 생성했다면 합치기 전에 한쪽 ID와 링크를 바꾼다.

합칠 때는 각 작업의 세션 파일을 모두 남기고 작업 카드의 최신 상태를 사람이 확인한다.
STATUS/CHANGELOG 충돌은 양쪽 내용을 읽어 해결하며 한쪽 파일로 일괄 덮어쓰지 않는다.
다른 브랜치 통합 후 영향받는 테스트를 다시 실행한다. 이력 rewrite·강제 push는 하지 않는다.
도구 권한/네트워크/회사 정책 차이로 실행 못 한 검증은 받는 PC의 다음 행동에 남긴다.

## 새 세션에 복사할 프롬프트

```text
이 저장소의 AGENTS.md, CONTRIBUTING.md, docs/work/README.md, docs/work/STATUS.md와
docs/work/tasks/<작업ID>.md 및 그 카드에 연결된 최신 세션을 읽어줘.
Git 상태·현재 브랜치·기준 커밋과 실제 구현부터 확인하고 사용자 변경은 보존해줘.
이번 작업은 <작업ID>의 <구체적 범위>로 제한해줘. 계획만 있는 다른 카드는 구현하지 마.
작업 카드의 담당/상태와 새로운 세션 파일에 진행·실행한 검증·미검증·다음 행동을 남겨줘.
검증된 단계는 커밋 규칙과 CHANGELOG를 지켜 커밋하고, push는 요청할 때만 해줘.
회사/고객 자료는 읽거나 기록하지 말고 저장소의 가상 코드만 써줘.
```

새 환경 준비만 원하면 `<구체적 범위>`를 “환경 구성과 해당 영역 테스트, 기능 구현 제외”로 지정한다.
이 기록은 AI가 지침을 실제로 준수했는지 자동 강제하거나 두 AI의 대화를 실시간 동기화하지 않는다.
