## 목적과 승인 범위

사용자가 "저장 파일이 잠겨서 안 열린다"고 알렸다. 원인은 조사 파일이 아니라 작성 잠금 파일이다. 창이 비정상 종료되면 잠금 파일이 남고,
다음 열기가 거부된다. 잠금 복구 명령은 소유 프로세스 종료를 확인해야 하는데 Windows의 프로세스 번호 재사용 때문에 거절될 수 있다.
사용자가 두 안(잠금 파일 없애기 / VS Code 내부 저장소) 중 "잠금 파일 없애기"를 골랐다.

## 범위 밖

- 저장 위치·형식 변경. `.branch-investigation/workspace.json`, 백업, 원자 교체는 그대로다.
- 충돌 때 자동 다시 읽기나 병합. 충돌한 창은 저장을 거절하고 창 다시 불러오기를 안내만 한다.
- 이전 버전이 남긴 잠금 파일의 자동 삭제(읽지 않고 그대로 둔다).

## 완료 조건

- [x] 열 때 잠금 파일을 만들지 않고, 남아 있는 잠금 파일이 열기·저장을 막지 않는다.
- [x] 두 창이 열어도 먼저 저장된 내용을 나중 창이 덮어쓰지 않는다(revision·해시 검사).
- [x] 잠금 복구 명령 제거, README·CHANGELOG·STATUS 갱신, VSIX 재빌드.
- [x] 설치된 VS Code의 Host 테스트(record·restart·Restricted Mode)와 VSIX 별도 설치 확인.

## 진행과 검증

확장 단위 46개, Host의 record·restart·Restricted Mode, VSIX 감사와 별도 설치 확인 통과. 처음엔 VS Code 업데이트 대기로 Host가 거부됐고, 사용자가 업데이트한 뒤 다시 돌렸다. 상세는 세션 기록.
