## 이번 범위

위치 재연결 명령에 같은 파일의 텍스트 일치 후보 제안을 추가한다. 저장 형식과 Python 엔진은 건드리지 않는다.

## 실제 변경

- `src/navigation/anchorResolver.ts`: `anchorCandidates()` 추가. 현재 문서에서 저장 스니펫과 같은 텍스트를 모두 찾아
  저장 당시 앞뒤 문맥과 맞는 길이, 저장 위치와의 줄 거리 순으로 정렬한다. 줄바꿈 형식이 바뀐 여러 줄 스니펫도 찾는다.
  200곳에서 검색을 멈추고 상위 20개만 돌려주며 잘렸는지 알린다. 줄 시작 계산은 기존 `offsets()`와 함께 쓰도록 분리했다.
- `src/extension.ts`: `repairAnchor`가 후보 목록(문맥 일치 정도, 줄 이동량, 해당 줄 미리보기)을 보여 주고, 고른 위치를 연 뒤
  확인을 받아 기존 `service.repair()`로 연결한다. 편집기 선택이 있으면 목록 끝에 "현재 선택 범위로 재연결"을 함께 낸다.
  후보가 없으면 기존 선택 범위 흐름 그대로다. 현재 연결 범위와 같은 후보는 목록에서 뺀다.
- `package.json`: 명령 제목을 "위치 재연결 (후보 찾기·선택 범위)"로 변경.
- `test/unit/anchor.test.ts`: 후보 검색 테스트 1개. `test/host/index.ts`: 후보 제안·거절·확인 시나리오 1개.
- 확장 README, CHANGELOG, STATUS(TASK-011 행, TASK-010의 PR #3 병합 반영), TASK-010 카드의 병합 사실.

## 미검증·문제·결정

- Host의 새 시나리오와 기존 7개 시나리오를 이 변경으로 다시 돌리지 못했다. 후보 목록 UI는 사람 손으로도 확인하지 않았다.
- 그래서 VSIX를 다시 만들지 않았다. `release/`의 VSIX는 이전 빌드 그대로다.
- Python 쪽은 바꾸지 않아 다시 돌리지 않았다(직전 세션에서 main 기준 193개 통과).
- 결정: 별도 명령을 만들지 않고 기존 `repairAnchor`를 넓혔다(원본 지시서 8절의 명령 계약). 검색은 열린 문서 텍스트 기준이라 미저장 변경도 반영한다.
- 한계: 텍스트가 한 글자라도 바뀌면 후보가 없다. 아주 짧은 스니펫은 후보가 많아 문맥 표시에 의존한다.
- 단위 테스트를 처음 쓸 때 기대 열 값을 한 번 잘못 적어 실패했고(이모지 UTF-16 길이), 기대값을 고쳤다. 구현은 바꾸지 않았다.
