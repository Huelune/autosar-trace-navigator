목표 하나를 전달용 문서와 시각화용 그림으로 내보내는 명령을 추가한다. 저장 형식과 Python 엔진은 건드리지 않는다.

## 실제 변경

- `src/ui/exporter.ts`(새 파일): 형식 네 가지의 글을 만드는 순수 함수.
  - 전달용 Markdown: 머리말, 목표 설명, 경로 요약(트리와 같은 갈래 묶음), 단계별 상태·위치·이어진 곳·이유·메모·근거, 코드(선택).
    기록한 글은 인용 줄로 넣어 Markdown 구조로 해석되지 않게 하고, 코드 울타리는 코드 속 백틱보다 길게 잡는다.
  - 시각화용 HTML: 스크립트·외부 파일·네트워크 없는 한 파일. CSS로 그린 위에서 아래 트리, 상태별 테두리, 현재 단계 강조, 단계별 접힌 메모와 코드.
  - 시각화용 Mermaid: `flowchart TD` 글. 관계 종류를 선 이름표로, 상태를 선 모양으로 표시. 코드 본문은 넣지 않는다.
  - 파일 이름은 목표 이름에서 만들고 파일 시스템이 거부하는 문자를 바꾼다.
- `src/extension.ts`: `exportGoal` 명령. 트리에서 고른 목표 또는 현재 목표 → 형식 선택 → 저장 위치 선택 → 쓰기. 테스트용 `save` 교체 지점 추가.
  완료 알림에는 경로를 적지 않는다. 쓰기 실패는 종류와 할 일만 알린다.
- `package.json`: 명령 등록, 목표 우클릭 메뉴와 트리 상단 **…** 메뉴.
- `test/unit/domain.test.ts` 1개, `test/host/index.ts` 시나리오 1개.
- 확장 README, CHANGELOG, STATUS(TASK-019 행, TASK-018의 PR #11 병합 반영), `release/` VSIX.

## 미검증·문제·결정

- Mermaid 글을 실제 Mermaid 도구에서 그려 보지 않았다. 글의 모양만 테스트했다.
- 저장 위치 대화상자, 완료 알림의 "열기", HTML의 인쇄 결과는 사람이 조작해 보지 않았다. 단계가 많아 옆으로 넓어진 그림도 보지 않았다.
- 문제와 수정: 처음 만든 경로 요약이 갈래 안의 다음 단계를 갈래 첫 단계와 같은 깊이로 적었다. 예시를 눈으로 보고 발견해 트리와 같은 묶음 규칙으로 고치고 테스트에 넣었다.
- 결정: 형식 네 가지와 내용 구성은 담당자가 정했다. 전달용에 코드 제외 형식을 둔 것은 코드 본문 없이 넘겨야 하는 경우를 위해서다.
- 결정: 시각화용 HTML은 라이브러리 없이 CSS로만 그렸다. 인터넷 없는 PC에서 열려야 하기 때문이다.
- 한계: 모든 형식에 작업 폴더 기준 파일 경로와 기록한 이유가 들어간다. 가리는 기능은 없다.
- Python 쪽은 바꾸지 않아 다시 돌리지 않았다.
