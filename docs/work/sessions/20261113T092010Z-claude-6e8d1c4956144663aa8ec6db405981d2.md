## 미검증·문제·결정

- 함수 목록 화면을 사람이 직접 조작해 보지 않았다. 실제 크기의 범위에서 첫 조회 시간과 5,000개 목록의 반응을 재지 않았다.
- 결정: 엔진에 검색어를 보내지 않고 목록 전체를 한 번 받아 VS Code 목록이 거르게 했다. 검색어마다 범위를 다시 파싱하지 않기 위해서다.
  엔진의 기존 검색 함수(토큰 검색·페이지)는 쓰지 않았다.
- 결정: 캐시는 메모리에만 둔다. 파일 하나만 바뀌어도 전부 비운다. 어느 결과가 그 파일에 기대는지 따지지 않는다.
- 한계: 작업 폴더 밖 파일의 변경은 알아채지 못한다. 파일 변경 알림이 늦게 오는 짧은 순간에는 옛 결과가 나올 수 있다.
  옛 결과로 이동할 때는 편집기 내용과 다르면 이동하지 않고 다시 조회하라고 알린다.
- 한계: 5,000개를 넘는 범위는 이름순 앞부분만 나온다.
